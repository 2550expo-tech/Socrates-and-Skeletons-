# Traceability: Problem → FR → Design → Code → Test

เอกสารนี้ผูกทุกฟีเจอร์ในแอปกลับไปที่ Functional Requirement ตาม M1 Team Charter (อ้างอิง SRS v1.3) เพื่อรักษา Golden Thread ของรายวิชา

> ⚠️ ข้อความ FR ด้านล่างสรุปจาก M1 Charter ทีมควรตรวจเทียบกับถ้อยคำใน SRS v1.3 ฉบับจริงอีกครั้ง และเติม NFR-1 ถึง NFR-5 ให้ตรงกับเอกสาร

## Problem
ผู้ใช้ที่รับ-จ่ายผ่าน mobile banking บ่อยมักเลื่อนการจด เพราะต้องกรอกซ้ำและหาสลิปเอง ข้อมูลจึงไม่ครบ และเห็นเพียงยอดคงเหลือ แต่ไม่เห็นว่าเงินจะหมดเร็วแค่ไหน

## การเปลี่ยนแปลงจาก M1 Charter (ต้องอัปเดต SRS)
- **29 ก.ย. 2569 — FR-3:** ผู้ใช้ขอ "จดรายการด้วยเสียง" (พูดว่า "ข้าว 50 บาท" แล้วบันทึกเป็น ข้าว ฿50) จึงย้าย FR-3 เข้ามาในแอป: เสียงแปลงเป็นข้อความด้วยระบบของมือถือ/เบราว์เซอร์ แล้วแอปแยกเป็นรายการให้ตรวจก่อนกดบันทึก ต้องเพิ่ม FR-3 กลับเข้า Scope ใน SRS/Charter
- **27 ก.ย. 2569 — FR-4:** ทีมตัดสินใจให้แอป "อ่านสลิปและคำนวณให้ทันทีเมื่อเปิดแอป" สลิปที่อ่านได้มั่นใจ ≥ 80% ทุกช่องจะเข้ายอดเงินโดยไม่ต้องกดยืนยัน (ปิดได้ในตั้งค่า และย้อนกลับได้) ส่วนสลิปที่ไม่ชัดยังเป็นแบบร่าง Charter เดิมเขียนว่า "สลิปเป็น draft จนผู้ใช้ยืนยัน" ต้องแก้ข้อความ FR-4 ใน SRS/Charter ให้ตรง

## Scope
- **อยู่ใน MVP:** FR-1, FR-2, FR-4, FR-5, FR-6 และ FR-3 บันทึกด้วยเสียง (เพิ่ม 29 ก.ย.)
- **นอก MVP (ยังไม่ทำในแอปนี้):** UC-7 Accountability Mode, UC-8 Offline เต็มระบบ, การเชื่อม Gmail/LINE

## FR-6 Money Runway

**Requirement:** ประมาณวันที่ยอดเงินอาจต่ำจากค่าเฉลี่ยรายจ่าย 7 วัน

**นิยามที่ตรวจสอบได้ (ตอบ feedback เรื่อง "Low balance" ใน SRS):**
- **เส้นเงินสำรอง (Low line):** จำนวนที่ผู้ใช้ตั้ง ค่าเริ่มต้น ฿500 "เงินต่ำ" = ยอดคงเหลือ ≤ เส้นนี้
- **ค่าเฉลี่ยต่อวัน:** รายจ่ายที่ยืนยันแล้วใน 7 วันล่าสุด (วันนี้ + 6 วันก่อน) ÷ จำนวนวันที่ใช้แอปมาแล้ว (สูงสุด 7)
- **Runway (วัน):** ⌊(ยอดคงเหลือ − เส้นสำรอง) ÷ ค่าเฉลี่ยต่อวัน⌋
- **Depletion date:** วันนี้ + Runway
- **สถานะ:** < 7 วัน = critical, < 14 วัน = watch, ≥ 14 วัน = healthy

|---|---|---|
| ค่าเฉลี่ยนับวันที่ไม่ได้ใช้เงินด้วย | `averageDailyExpense` | TC-12 |
| ผู้ใช้ใหม่หารด้วยจำนวนวันที่ใช้จริง | `averageDailyExpense` | TC-13 |
